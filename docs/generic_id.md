# Generic ID Abstraction in magic_orm

## Overview

Magic_orm now supports generic ID types through the `Model` trait. Previously, all models were hardcoded to use `i64` as the primary key type. This refactor introduces a generic associated type `Id` that can be any type satisfying the required bounds.

## Changes Made

### 1. Model Trait (`magic/src/model/core.rs`)

The `Model` trait now defines `Id` as an associated type with the following bounds:

```rust
pub trait Model: ModelMeta + Sized + Send + Unpin + for<'r> sqlx::FromRow<'r, sqlx::sqlite::SqliteRow> {
    type Id: Send + std::fmt::Display + Clone + Eq + std::hash::Hash;
    
    fn id(&self) -> &Self::Id;
    // ... other methods
}
```

### 2. HasFK Trait (`magic/src/relations/traits.rs`)

Updated to remove `Copy` constraint and use `Clone + Eq + Hash`:

```rust
pub trait HasFK<P>
where
    P: Model,
    P::Id: Clone + Eq + std::hash::Hash,
{
    fn fk_for_parent() -> &'static str;
    fn fk_value(&self) -> P::Id;
}
```

### 3. Public API Methods

The following methods now use the model's generic ID type instead of hardcoded `i64`:

- `get_by_id(executor, id: Self::Id)`
- `delete_by_id(executor, id: Self::Id)`
- `put(executor, id: Self::Id, new: &NewStruct)`

### 4. Eager Loading

`EagerQueryBuilder` and `WithMany` now use generic `P::Id` for parent-child relationships:

```rust
pub struct WithMany<P: Model, C> {
    pub parents: Vec<P>,
    pub children: HashMap<P::Id, Vec<C>>,
}
```

### 5. SQLx Bounds

Added `sqlx::Encode` and `sqlx::Type` bounds where needed for database operations:

```rust
P::Id: Clone + Eq + std::hash::Hash + for<'q> sqlx::Encode<'q, sqlx::Sqlite> + sqlx::Type<sqlx::Sqlite>
```

## Usage

### Traditional i64 ID (still works)

```rust
#[derive(MagicModel, Debug)]
#[magic(table = "users")]
pub struct User {
    pub id: i64,  // ID type is inferred as i64
    pub name: String,
}

// Usage
let user = User::get_by_id(&pool, 1i64).await?;
```

### Custom ID Type (example)

To use a custom ID type, define your model with that type:

```rust
#[derive(MagicModel, Debug)]
#[magic(table = "users")]
pub struct User {
    pub id: String,  // Now using String as ID
    pub name: String,
}

// The trait will use String as the Id type
impl Model for User {
    type Id = String;  // This is generated by the derive macro
    // ...
}
```

## Limitations (Next Steps)

1. **Insert returns i64**: The `insert` method still returns `i64` because SQLite's `last_insert_rowid()` always returns an integer. For non-i64 ID types, you'll need to:
   - Generate the ID before insertion
   - Modify the `insert` method to return the generic ID type
   - Handle ID generation in a database-agnostic way

2. **SQLite-specific**: Currently only SQLite is supported. Other databases may handle auto-increment IDs differently.

3. **sqlx::Encode/Type bounds**: For custom ID types, you need to implement `sqlx::Encode` and `sqlx::Type` for your ID type.

## Testing

All existing tests pass with the generic ID changes. The abstraction maintains backward compatibility with `i64` IDs while enabling future support for `String`, `Uuid`, or other ID types.
