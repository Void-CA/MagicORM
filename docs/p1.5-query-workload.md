# P1.5: Query Ergonomics — Thalos Workload Analysis

## Current QueryBuilder API

### Available Methods

| Method | SQL Equivalent | Status |
|--------|---------------|--------|
| `filter(col, op, value)` | `WHERE col op ?` (AND) | ✅ |
| `or_filter(col, op, value)` | `WHERE col op ?` (OR) | ✅ |
| `filter_in(col, values)` | `WHERE col IN (?, ...)` | ✅ |
| `order_by(col, asc)` | `ORDER BY col ASC/DESC` | ✅ |
| `limit(n)` | `LIMIT n` | ✅ |
| `offset(n)` | `OFFSET n` | ✅ |
| `count()` | `SELECT count(*)` | ✅ |
| `join::<U>()` | `LEFT JOIN` | ✅ |
| `select(cols)` | `SELECT cols` | ✅ |
| `first_query()` | `LIMIT 1 + ORDER BY id DESC` | ✅ |
| `with_many::<C>()` | Eager loading | ✅ |

### Executor Methods

| Method | Returns | Status |
|--------|---------|--------|
| `fetch_all(executor)` | `Vec<T>` | ✅ |
| `fetch_one(executor)` | `T` (error if missing) | ✅ |
| `fetch_optional(executor)` | `Option<T>` | ✅ |
| `execute(executor)` | `u64` (rows affected) | ✅ |

## Thalos Query Workload

### Q1: Get execution session by ID

```rust
ExecutionSession::query()
    .filter("id", "=", session_id)
    .fetch_one(&db)
    .await?;
```

**Status:** ✅ Supported (use `get_by_id` or this pattern)

### Q2: Get observations for a session (ordered by time)

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .order_by("timestamp", true)
    .fetch_all(&db)
    .await?;
```

**Status:** ✅ Supported

### Q3: Time window query (most important)

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .filter("timestamp", ">=", start)
    .filter("timestamp", "<", end)
    .order_by("timestamp", true)
    .fetch_all(&db)
    .await?;
```

**Status:** ✅ Supported (multiple filters chain as AND)

### Q4: Paginated query

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .order_by("timestamp", false)
    .limit(1000)
    .offset(2000)
    .fetch_all(&db)
    .await?;
```

**Status:** ✅ Supported

### Q5: Count observations

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .count()
    .fetch_one(&db)
    .await?;
```

**Status:** ⚠️ Partial — `count()` returns `T` (model type), not integer. Needs fix.

### Q6: Check existence

```rust
ExecutionSession::query()
    .filter("status", "=", "running")
    .exists(&db)
    .await?;
```

**Status:** ❌ Not supported — no `exists()` method

### Q7: Get latest observation

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .order_by("timestamp", false)
    .limit(1)
    .fetch_optional(&db)
    .await?;
```

**Status:** ✅ Supported

### Q8: Filter by multiple values

```rust
Observation::query()
    .filter_in("sensor", ["sensor_0", "sensor_1", "sensor_2"])
    .fetch_all(&db)
    .await?;
```

**Status:** ✅ Supported

### Q9: OR filter

```rust
ExecutionSession::query()
    .or_filter("status", "=", "running")
    .or_filter("status", "=", "paused")
    .fetch_all(&db)
    .await?;
```

**Status:** ⚠️ Partial — `or_filter` exists but there's no way to mix AND/OR groups

### Q10: Ordered with multiple columns

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .order_by("timestamp", false)
    .order_by("id", false)
    .fetch_all(&db)
    .await?;
```

**Status:** ❌ Not supported — `order_by` only supports single column

### Q11: Select specific columns

```rust
Observation::query()
    .select(&["sensor", "value", "timestamp"])
    .filter("session_id", "=", session_id)
    .fetch_all(&db)
    .await?;
```

**Status:** ✅ Supported

### Q12: Join with related model

```rust
ExecutionSession::query()
    .join::<Observation>()
    .filter("observations.session_id", "=", session_id)
    .fetch_all(&db)
    .await?;
```

**Status:** ✅ Supported

## Gap Analysis

| Gap | Priority | Impact |
|-----|----------|--------|
| `count()` returns `T` instead of integer | **High** | Breaks expected semantics |
| No `exists()` method | **Medium** | Need raw SQL for existence checks |
| Single `order_by` only | **Medium** | Can't sort by multiple columns |
| No `is_null`/`is_not_null` filters | **Low** | Need raw SQL for NULL checks |
| No `between` filter | **Low** | Can chain two filters instead |
| No `like` filter | **Low** | Can use `filter("col", "LIKE", ...)` |

---

## Design Decisions

### 1. Fix `count()` semantics

Current: `count()` sets `count_mode = true`, but `fetch_one` returns `T`.

Option A: Add `fetch_count()` method that returns `i64`
Option B: Create `CountQuery` type that only has `fetch_one() -> i64`

**Decision:** Option A — simpler, less API surface.

### 2. Add `exists()` method

```rust
Observation::query()
    .filter("session_id", "=", session_id)
    .exists(&db)
    .await?;
```

Implementation: `SELECT 1 FROM ... LIMIT 1` + `fetch_optional`. Returns `bool`.

### 3. Add multiple `order_by` support

Current: `order_by` overwrites previous value.

Option A: Chain multiple `order_by` calls
Option B: Accept slice of `(col, asc)` tuples

**Decision:** Option A — more ergonomic, matches existing pattern.

### 4. Add NULL filter helpers

```rust
.filter_null("deleted_at")
.filter_not_null("email")
```

Implementation: `WHERE col IS NULL` / `WHERE col IS NOT NULL` (no binding needed).

---

## Minimal API Additions

1. `fetch_count(executor) -> Result<i64>` — for count queries
2. `exists(executor) -> Result<bool>` — for existence checks
3. `order_by(col, asc)` — change to accumulate, not overwrite
4. `filter_null(col)` / `filter_not_null(col)` — NULL checks

No new filter operators needed — `filter("col", "LIKE", ...)` works for pattern matching.
